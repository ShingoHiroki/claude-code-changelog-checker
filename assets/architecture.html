GITHUB ACTIONS PIPELINE

Changelog Checker 構成図

Claude Code（@anthropic-ai/claude-code）の新バージョンを検知し、リリースノートを「さくらのAI Engine」で日本語翻訳して Discord / Slack に通知、GitHub Pages で公開するまでの全体構成。

  • GitHub Actions
  • さくらのAI Engine（gpt-oss-120b）
  • Discord Webhook
  • Slack Webhook
  • GitHub Pages

概要

スケジュール実行を起点に、外部サービスとどう連携するかの全体像。

  1. 最新バージョン取得 — GitHub Releases API から最新・未取得リリースを取得する
  2. 前回バージョンと比較 — state/last-version.txt と比較し、差分がなければ終了する
  3. 日本語翻訳 — さくらのAI Engine（gpt-oss-120b）でカテゴリ別本文を翻訳する
  4. Webhook 通知 — Discord は Embed で全件、Slack は Block Kit でサマリーのみ。失敗時はプレーンテキストにフォールバックする
  5. サイトデータ書き出し — 構造化翻訳を docs/data/<version>.json に出力する
  6. commit / push — state と docs/data/ をコミットバックし、GitHub Pages に自動反映される

詳細

分類・翻訳の2系統、フォールバック、DRY_RUN / force_notify、バックフィルまで含めた処理フロー。

翻訳は2系統

通知用の行翻訳（translateToJapanese()）とサイト用の構造化翻訳（translateToStructuredJapanese()）は別リクエスト。件数サマリーは翻訳前の英語分類から算出する。

通知の順序と整合性

複数バージョンを検知した場合は古い順にバージョンごと個別通知。全リリースの通知成功後に state 更新とサイトデータのコミットを行う。

サイトリンクの導出

通知に載せる公開サイト URL は SITE_URL → GITHUB_REPOSITORY の順で導出。導出できない場合はリンクを省略する。

初回バックフィル

npm run backfill で過去リリースの docs/data/*.json を一括生成。生成済みはスキップされるため中断・再実行に強い。
